# MyCalculator 设计文件

日期：2026-10-25
状态：等 Bryan 确认

## 1. 为什么做

App Store 上算财务计划、房贷、车贷、供期和利息的 App 几乎都要订阅。MyCalculator 是一个**完全免费**的马来西亚财务计算器，先给自己用，也可以用 QR 分享给别人。它是 Woo Brothers 系列 PWA 的一员，沿用同一套做法和外观。

## 2. 目标

1. 五个计算器，每个都做到详细（Bryan："全部要，越详细越好"），五个一起做，不分批：
   - 复利 Compound Interest
   - EPF
   - 房贷 Home Loan
   - 车贷 Car Loan（Hire Purchase）
   - 所得税 Income Tax（个人和公司）
2. 算好的 projection 可以取名存起来，以后打开再看。
3. 导出 PDF 和 Excel。
4. 三种语言：English / 中文 / BM。默认 English，第一次打开先选语言。
5. 沿用系列 App 的 8 种主题和 Settings 页。
6. 符合 [APP-STANDARDS.md](https://github.com/bryanwoo988/woobrothers.my/blob/main/APP-STANDARDS.md)：QR、分享链接、版本号、"更新了什么"弹窗、有新版本先问、离线缓存只清理自己的。

## 3. 不做什么（Non-goals）

- 不收费，不做锁头和付费解锁。参考截图里的 "FREE" 标签和锁头不照抄（我的判断：跟做这个 App 的原因相反，系列 App 也全部免费）。
- 不上传任何资料，没有账号，不做云端同步。
- 不是报税工具：所得税计算器只做估算，不替代 e-Filing。
- 不提供理财建议，不推荐银行或产品。
- 不做 Read Aloud（旧 App 有，计算器用不上）。

## 4. 绝对不能出现的结果（Anti-goals）

- **算错数字。** 比没有计算器更糟。每条公式都要有测试，用银行计算器、LHDN、KWSP 公布的例子或手算对数。
- **规则过期还不知道。** 税率、EPF 比例、印花税每年可能变。App 必须显示"规则更新至 YYYY-MM-DD"和来源，规则不能写死在代码里。
- **资料丢失。** 存下的 projection 被系统清掉，用户又没备份。
- **App 变得很重。** 不为了一个功能塞几 MB 的库或字体。

## 5. 限制（Constraints）

来自系列 App 的惯例（参考 `bryanwoo988/Entomology`，最新、有测试的那个）：

- 纯静态 PWA：没有 build step，不用 npm 依赖，不用 CDN。原生 ES modules + CSS。
- 放在 GitHub Pages：`https://bryanwoo988.github.io/MyCalculator/`。
- Service worker 预先缓存全部文件，装好后可以离线使用；缓存名称用自己的前缀（`mycalc-`），只清理自己的旧缓存。参照 Entomology 的 `tools/build-sw.mjs`。
- 测试用 `node --test tests/*.test.js`，加上浏览器测试页 `tests/index.html`。
- 资料存在 localStorage（参照 Entomology `js/prefs.js`：存储可能不存在或会出错，要能退回到只用内存）。
- 更新提示用共用的 `whatsnew.js`；更新记录放在 `data/releases.json`，每次发布在最前面加一条，三种语言都写。
- QR 离线生成（参照 Entomology `js/qrcode.js` / `tools/verify-qr.mjs`），不用外部网站。

## 6. 做法（Approaches）

### 6.1 技术栈

只有一个合理选项：沿用系列 App 的纯静态 PWA。Bryan 已经确认用 PWA，跟之前做的差不多。原生 iOS 要每年 US$99，也不能直接用 QR 分享给 Android 用户；只装在自己手机又没办法分享。

### 6.2 PDF / Excel 导出（Bryan 选了 A）

| | A. 全部自己做（✅ 已选） | B. 把第三方库文件放进 repo |
|---|---|---|
| PDF | 专门做打印版排版（`@media print`），调用 `window.print()`，用户选"存为 PDF" | jsPDF |
| Excel | 自己写一个小工具生成真正的 `.xlsx`（ZIP 用 store 模式不压缩 + SpreadsheetML），可以分多个 sheet | SheetJS（约 1MB） |
| 中文 | 用系统字体，中文直接显示 | 要打包中文字体，好几 MB |
| 依赖 | 零依赖 | 违反"不用依赖" |

选 A 的理由：零依赖，中文不用打包字体。代价：存 PDF 要多按一步；`.xlsx` 生成器要写测试，确认 Excel、Numbers、Google Sheets 都打得开。

**风险，要先验证：** 从主屏幕打开的 iOS PWA 能不能调出 `window.print()`，目前还不确定。实现的第一步是做一个很小的测试页，部署后由 Bryan 在自己的 iPhone 上试。如果不行，退路是：用 Web Share 分享打印版 HTML，或者提示用户改在 Safari 里打开再打印。到时再跟 Bryan 决定。

其他工作不用等这个测试结果（我的判断）：Excel 导出不受影响，打印版排版在两种情况下都用得上。只有"按钮按下去之后做什么"要等结果再定。

## 7. 已决定的部分

### 7.1 外观、语言、Settings

- 第一次打开：语言选择页（English / 中文 / BM），默认选中 English。选了以后才进入 App（参照 Entomology 的 `chosen` 旗标）。
- Settings 照搬系列 App：
  - Language：English / 中文 / BM
  - Theme：System / Light / Dark
  - Light theme：Classic、Paper、Mint、Lavender
  - Dark theme：Midnight、OLED Black、Slate、Grape
  - 字体大小（系列 App 都有）
  - 去掉 Read Aloud
- 8 种主题的色值直接从 Entomology `css/app.css` 搬过来。
- 中文用简体（系列 App 的 `zh`）。
- 参考图片在 `docs/reference/`：`home-list-reference.jpg`（首页列表）、`settings-reference.jpg`（Settings）、`app-logo.png`（App logo，Bryan 指定，直接使用）。
- 首页：五个计算器的列表，样式参考 Bryan 提供的截图（圆角卡片、左边图标、标题和一行说明），但不放锁头和 FREE 标签。
- About：QR、网址、"分享 App 链接"按钮、`WhatsNew.label()` 版本号和日期、更新记录、规则来源列表，以及免责声明（"估算结果，仅供参考，不构成财务建议"）。

### 7.2 存记录（Bryan：projection 可以记录方便过后可以看回）

- 每次计算都可以"存起来"，名字可以自己取（例如"Setia Alam 那间，90% 贷款"）。
- 存的内容：计算器类型、所有输入、用了哪一版规则（ruleset id）、当时的结果摘要、存的日期。
- 打开旧记录时，先显示当时的结果。如果规则已经更新，提示"规则已更新，用新规则重算？"，并把新旧结果并排显示。
  - "规则更新"只指同一份规则的修订号变了（同一个 YA 或同一年的数字被修正）。
  - 年份本身是输入：YA2025 的税务记录永远用 YA2025 的规则，不会自动换成 YA2026。想看新年份，就复制一份记录，改年份。（我的判断）
- 记录列表按计算器分类，可以改名、复制一份来改数字、删除。
- **备份和还原**：导出一个 JSON 文件（包括所有记录和设置），可以导入。About 页提示 iOS 可能清理 PWA 资料，建议定期备份。
- 资料只存在手机里。

### 7.3 规则资料（税率、EPF、印花税等）

- 放在 `data/rules/` 底下的 JSON，按年份和项目分开，例如 `tax-personal-YA2025.json`、`epf.json`、`property-costs.json`、`hire-purchase.json`。
- 每一条数字都附上：来源网址、来源名称、生效日期，以及"via"（直接打开官方页面还是只看过搜索摘要；系列 App 的惯例）。
- 来源优先用官方的：LHDN / hasil.gov.my、KWSP / kwsp.gov.my、BNM、法律原文或宪报。官方打不开时，可以暂时用可信的二手来源，但要标明。
- App 内显示"规则更新至……"，About 页列出全部来源。
- **怎么更新到用户手上（我的判断）：** 规则 JSON 跟着 App 一起发布，没有单独的线上更新。改了规则就发一个新版本，走系列 App 现有的流程：service worker 发现新版本 → "有新版本可以更新" → "更新了什么"弹窗写明改了哪条规则。这样离线时也一定有一份完整、一致的规则。
- **过期提醒（我的判断）：** 每份规则文件有 `reviewBy` 日期（例如税率文件是下一个 YA 开始的日期，EPF 文件是下一次分红一般公布的时间）。过了这个日期，计算器顶部显示一行提醒"这些规则可能已过期，请留意更新"，但照样可以计算。测试时用假日期来检查提醒会不会出现。
- **规则版本（我的判断）：** 每个计算器各自有 ruleset id，例如 `tax-personal-YA2025@2`。`@` 后面的修订号在同一年份内修正数字时加 1。旧的规则文件保留在 repo 里，不删除。

### 7.4 五个计算器

以下功能清单是**我的提议**，用来落实"越详细越好"。所有数字（比率、上限、阶梯）实现时都要再对照官方来源核对，放进 `data/rules/`；这里列出的数字是 2026-10-25 查到的，只用来说明结构。

范围：Bryan 要求五个全部、越详细越好、一起做，所以下面整份清单都是 v1 的范围，不再另外分出"先做的小版本"。

**计算方法和取整（我的判断）。** 测试的预期值都按这些方法来算：
- 房贷 / 车贷（reducing balance）：月供用标准年金公式（monthly rest）计算。马来西亚很多房贷其实是 daily rest，银行月结单上的利息会因此跟 App 有些微差距，结果页要写明这一点。月供显示到仙（四舍五入）。
- 所得税：先按阶梯算出精确值，显示到仙。不擅自做 LHDN 没有明文规定的取整。
- EPF 分红：实现时先查 KWSP 公布的计算方式（按日余额还是按月余额），照官方的做；查不到的话，用按月余额近似计算，并在结果页注明。
- 所有比率、阶梯、上限都用来源里的原始数字，不预先取整。

每个计算器的共同部分：
- 输入表单（有合理默认值，每个字段都有简短说明）
- 结果摘要卡
- 图表（自己用 SVG 画，不用库）
- 明细表（逐月 / 逐年，可以切换）
- 存起来 / 导出 PDF / 导出 Excel

#### a. 复利 Compound Interest

- 输入：本金、定期投入（每月或每年）、投入放在期初还是期末、年利率、复利频率（每年 / 每季 / 每月 / 每日）、年数。
- 进阶：每年增加投入 %、通胀率（同时显示名义值和实际购买力）。
- 反推：要在 N 年后达到目标金额，每月需要投入多少。
- 输出：最终金额、总投入、总利息、逐年明细、本金对利息的堆叠图。

#### b. EPF

- 输入：现在年龄、月薪、每年加薪 %、三个户口的现有余额（Akaun Persaraan / Sejahtera / Fleksibel）、员工缴纳率（默认 11%，可以调高）、雇主缴纳率（按规则：月薪 ≤ RM5,000 为 13%，> RM5,000 为 12%，待核对）、假设分红率（默认最近公布的那一年，2025 年为 6.15%，可以改）、每年自愿缴纳金额。
- 规则：新缴纳按 75% / 15% / 10% 分配到三个户口（2024 年 5 月 11 日起，55 岁以下）；分红按每个户口各自的余额计算；60 岁以后的缴纳率按规则表。
- 输出：到 55 岁和 60 岁时三个户口的余额、逐年明细、户口余额图。
- 不做：提款模拟（以后再说）。

#### c. 房贷 Home Loan

- 贷款：房价、贷款比例（margin of finance）或贷款金额、年限、利率。
- 利率变动：可以加多段，例如"第 1–3 年 3.9%，之后 4.3%"。
- 提前还款：一次性或定期，可以选"缩短年限"或"降低月供"。显示省下的利息和缩短的时间。
- 买房成本：
  - 首付
  - SPA 律师费和贷款合约律师费：按 Solicitors' Remuneration Order 2023 的阶梯，第一个 RM500k 为 1.25%（最低 RM500），RM500k–7.5m 为 1%，待核对；另加 SST
  - MOT 印花税：公民和永久居民按阶梯 1% / 2% / 3% / 4%；外国人的税率要另外核对，有来源说 2026 年起是 8%
  - 贷款印花税 0.5%
  - 首购屋印花税豁免：如果仍然有效，按规则表，可以勾选
  - 估价费、MRTA / MLTA、杂费（disbursement）：用户自己填，有说明
- DSR：月收入和现有的每月债务 → DSR %。只显示数字，不判断银行批不批。
- 输出：月供、总利息、总还款、买房总现金支出、逐月和逐年还款表、余额曲线、本金和利息比例图。

#### d. 车贷 Car Loan（Hire Purchase）

**法律变动：** Hire Purchase (Amendment) Act 2026 从 2026-06-01 起生效，新签的 HP 改用 reducing balance + EIR，flat rate 和 Rule of 78 被废除；银行的宽限期到 2027-03-31（来源：BNM 消费者指南，实现时核对）。

- 算法二选一：
  - **Reducing balance / EIR（默认，新贷款）**：跟房贷一样的摊还计算。
  - **Flat rate（旧贷款）**：利息 = 本金 × 利率 × 年数，平均分摊；同时显示等值 EIR；提早还清时按 Rule of 78 计算利息回扣。
- 输入：车价、首付、贷款金额、年限、利率、算法。
- 提早还清：输入"第几个月还清"，显示要付多少、省多少。
- 两种算法对比：同一笔贷款并排显示总利息差多少。
- 输出：月供、总利息、EIR、还款表、余额曲线。

#### e. 所得税 Income Tax

- 年份选择（YA），每个年份一份规则文件。第一版做 YA2025，YA2026 等官方公布后再加。
- 个人（居民）：
  - 收入：受雇收入、花红、其他收入（租金、生意等，简单加总）
  - 扣除（reliefs）：按规则表列出每一项和上限，例如个人 RM9,000、EPF 加人寿保险上限 RM7,000，用户勾选并填金额，超出上限自动截断
  - 回扣：应课税收入 ≤ RM35,000 时 RM400；zakat 可以扣税
  - 税率阶梯：0%（首 RM5,000）到 30%（> RM2m），按规则表
  - PCB / MTD 已扣多少 → 显示要补税还是退税
  - 输出：应课税收入、每个阶梯的税额明细、实际税率、边际税率
- 个人（非居民）：统一 30%，没有扣除。
- 公司：
  - SME（条件按规则表：缴足资本和营业额上限）：阶梯税率，例如首 RM150k 为 15%、接下来 RM450k 为 17%、其余 24%，待核对
  - 非 SME：24%
  - 输入应课税收入 → 显示税额和明细
- 不做：股息税、资本利得税、房产盈利税（RPGT）这些较少用到的项目。以后有需要再加。

### 7.5 导出内容

- **PDF（打印版）**：App 名字、计算器名字、记录名字、日期、所有输入、结果摘要、图表、明细表（逐年；逐月太长时只放逐年，另外提示用 Excel 看逐月）、规则版本和来源、免责声明。按当前语言显示。
- **Excel**：第一个 sheet 放输入和摘要，第二个 sheet 放逐月或逐年明细。数字存成数字（不是文字），方便自己再算。
